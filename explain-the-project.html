Project overview

Incident Copilot — how the whole project works

A plain-English tour of the entire project: what it is, what it does, how it's built, and how to run it. Written for people who want to understand the whole thing without reading source code.

01The 30-second story

If you only read one section, read this.

Incident Copilot is a self-hosted web app that helps small engineering teams handle outages and security problems. It watches your logs, finds unusual activity, keeps a clean record of every incident, and can scan public code repositories for security issues — all from one dashboard. A backend written in Python powers the smarts; a React frontend gives it a friendly face. It's built to run on your own infrastructure, with no accounts and no user tracking.

03What it does

Six features, split across two products — an "Incident Manager" and a "Security Checker."

Incident Manager

Incident tracking

Every problem becomes a record: status, severity, timeline, root cause, and resolution. Perfect for demos and for real use.

Incident Manager

Log analysis & grouping

Massive log files are compressed into a handful of repeating patterns (via Drain3) so you can see what's actually happening.

Incident Manager

Anomaly detection

Trained on your history, its statistical engine (PyOD) flags error rates and patterns that look unusual — often before a customer notices.

Incident Manager

Semantic log search

Search logs in natural language ("why are checkouts failing?") using AI embeddings instead of exact keyword matches.

Security Checker

Repo security scanning

Give it a public repo URL (or a zip file) and it hunts for secrets, risky code, and bad config — scored 0–100 with an A–F grade.

Security Checker

LLM deep review

Optional AI review reads the trickiest findings in plain language and explains the risk and fix for each one.

04The two products

Incident Manager ●

The day-to-day home for on-call engineers:

  • Dashboard with live KPIs — active incidents, critical alerts, time-to-resolve.
  • Searchable incident list with filters for status and severity.
  • Incident detail pages with a real timeline of status changes.
  • Log viewer, semantic search, and analytics built from your data.

Security Checker ●

A security sidekick for public repositories:

  • Scan a repo or upload a zip without leaving the app.
  • Score and grade every scan (0–100, A–F) with sub-scores per category.
  • Crucial findings automatically become incident records.
  • History — compare past and present scans side by side.

06How data flows

  1. Logs come in (uploaded or streamed) and are stored in PostgreSQL.
  2. The parser (Drain3) collapses thousands of look-alike log lines into a few "patterns," so anomalies are easier to spot.
  3. The anomaly engine (PyOD) compares patterns against history and flags what looks unusual.
  4. Log lines are turned into embeddings, letting you search by meaning, not just keywords.
  5. Incidents, log events, and scan results are all served through the FastAPI API.
  6. The frontend talks to that API and shows everything: dashboards, filters, timelines, and analytics.
The API is the seam: every part of the UI talks to the real backend over /api/v1/... — nothing is hard-coded or faked on the frontend. That's why realistic demo data makes the whole app behave like production.

08The security scanner, up close

How a scan works

  • You submit a public repo URL (github.com, gitlab.com, bitbucket.org) or a zip file.
  • The scanner clones the repo and walks it safely (capped size and file count).
  • 20 built-in rules check for API keys, weak configs, risky code, and more.
  • Optional LLM deep review reads the most important files and explains each finding.
  • You get a score (0–100), a grade (A–F), sub-scores per category, and a summary.
  • Critical-and-high findings auto-create incidents, deduplicated across rescans.

Made to never fail hard

  • No OpenAI key? The scan still runs with rules only.
  • Big or weird repos get aborted safely instead of hanging.
  • Each host is allow-listed, so it only fetches from trusted sources.
  • Scan timeouts and crashes are reported cleanly as failed scans.
Security + incidents share a thread: a scan finding isn't just a report — it can become an incident in the Incident Manager, so everything lives in one place.

09Look and feel

The interface was redesigned to look and feel like a professional SaaS product:

  • Clean light theme by default, with a dark mode you can switch to from the top bar or settings.
  • Real data everywhere — every number is computed live from the API, never hard-coded.
  • Gentle motion: animated heroes, floating backgrounds, subtle transitions — all with "reduced motion" support for accessibility.
  • No gradients, no clutter — a disciplined color system instead.
  • Responsive: works on phones, tablets, and desktops.

10Quality & testing

Backend (Python)

  • 225 automated tests, all passing — no database required.
  • Covers API routes, log parsing, anomaly logic, security URL validation, the rules engine, scoring, and scan flows.
  • Run with python -m pytest -q.

Frontend (TypeScript)

  • Strict TypeScript catches type errors at build time.
  • Validated with npx tsc --noEmit, npm run lint, and npm run build.
  • Every page is checked for accessibility and responsive layout.

11How to run it

Three moving parts

  • Database: PostgreSQL 16 — start with docker-compose up -d or a local install.
  • Backend: from backend/, uvicorn app.main:app --reload (runs on port 8000).
  • Frontend: from frontend/, npm run start (runs on port 3000, proxies API calls to the backend).

Environment settings

  • Everything is configured by a backend/.env file (copy it from .env.example).
  • Required: the DATABASE_URL. Optional: an OPENAI_API_KEY for AI search and security deep review.
  • Never commit .env files or keys.

Demo data

  • A script loads 19 realistic incidents through the real API so dashboards look alive: python mock-data/load_mock_data.py.
  • See mock-data/explain-the-data.html for how to talk people through that data.

12Deployment & limits

Running in production

  • A Dockerfile plus docker-compose.yml for the backend and database.
  • A render.yaml blueprint for one-click hosting on Render (backend + managed PostgreSQL).

Know the limits

  • No user accounts or authentication. Anyone who reaches the server can use it.
  • So: don't expose the API directly to the internet — put an access layer in front.
Bottom line: a serious, self-hosted incident + security platform for small teams — real AI features, real data, real tests, and a clean interface, all in one repo.
